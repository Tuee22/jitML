## Sprint 36.1: Durable-State Dhall DSL Foundation and `jitml project init` [✅ Done]

**Status**: Done (reopened 2026-06-23; re-closed 2026-06-24) — the durable-state DSL
foundation; the lowest phase any consumer (Phases 4/5/10) needs, so every dependent
`Blocked by` edge points down to this sprint (rule M(a)).

**Dependencies**: none (foundation).

Introduce a closed, self-validating `jitml.dhall` `<project>` document — generated by
a new `jitml project init` — that expresses durable-state management as pure Dhall,
mirroring the hostbootstrap `<project>.dhall` idiom but standalone (no `Core.dhall`
dependency):

- `dhall/project/Schema.dhall` (committed vocabulary / anti-drift mirror): the closed
  `StoreKind` (`ObjectBucket`/`MessageTopic`), `StorePhase` (`Live`/`Retired`),
  `RetentionPolicy` (`KeepAll`/`LastN`/`MaxAgeSeconds`/`MaxBytes`/`LastNWithinAge`),
  `StoreEntry`, `StoreRegistry`, `Budget`/`PodResources`, and the Prelude-free lemmas
  `fitsWithin`/`storageFitsWithin`/`retentionWellFormed`/`writersAreLive`/`contractOK`.
  Writers are minted only through a closed `StoreId` union + exhaustive `merge`
  selector, so an undeclared store name is unnameable (the Dhall lift of
  `JitML.Coordinator.Topology`'s `newtype Topic`/`topicFor` discipline).
- `src/JitML/Project/Config.hs`: `FromDhall` decoders + `renderProjectConfigDhall` +
  `defaultProjectConfig`, mirroring `JitML.Service.BootConfig`
  (`defaultBootConfig`/`renderBootConfigDhall`); reflected-schema anti-drift via
  `JitML.Service.DhallSchema`.
- CLI `jitml project init` (`CLI/Spec.hs` + `App.hs` `runProjectInit`): writes a
  default, self-contained, self-validating `./jitml.dhall` (inline schema + data +
  `assert : contractOK self === True`), `--output`/`--force` like the hostbootstrap
  initializer.
- Lift `dhall/cluster/{Schema,resources}.dhall` from Text quantities onto Core-style
  Natural `Budget`/`PodResources` + `assert : fitsWithin …`, closing the un-asserted
  over-budget gap the SSoT comment (`resources.dhall:1`) already claims to hold.

### Exit Definition

- `jitml project init` emits a `./jitml.dhall` that `dhall type` accepts; re-running
  without `--force` refuses, with `--force` overwrites.
- Each illegal state is a typecheck failure: over-budget cluster, over-storage-quota, a
  writer targeting a `Retired` store, malformed retention (`LastN 0`), and a reference
  to an undeclared store.
- `renderProjectConfigDhall`/decoder round-trip and the `dhall/project/Schema.dhall`
  parity (anti-drift) test pass both directions in `jitml-unit`.
- The over-budget cluster (10752 vs 10240 MiB) fails `dhall type` after the
  `resources.dhall` migration.
