## POC Report-Card Knobs

Pinned in `cabal.project` for reproducibility across hosts; see
[phase-12-test-stanzas-and-cross-cluster.md](README.md#legacy-to-new-phase-map).

| Knob | Value | Purpose |
|------|-------|---------|
| `sl_epochs` | `5` | Report-card SL convergence knob; ProductRow fixed schedules are row-specific execution contracts of `10`, `15`, or `40` epochs |
| `sl_batch` | `64` | Canonical SL minibatch size for the convergence-check budget |
| `rl_steps` | `100_000` | Report-card RL convergence knob; ProductRow transition budgets come from the row's real trainer schedule, not this value |
| `rl_eval_episodes` | `25` | Per-eval episode count for the RL Evaluator |
| `az_games` | `200` | Self-play game count per AlphaZero generation in the convergence-check suite |
| `az_sims` | `400` | MCTS simulation budget per move in the AlphaZero convergence-check suite |
| `tune_trials` | `64` | Trial count for the report-card tuning workload |
| `tune_budget_per_trial` | `1_000` | Per-trial step budget for the report-card tuning workload |
| `xcluster_kind_nodes` | `2` | Future cross-cluster e2e stack node-count knob; current per-substrate local Kind configs use the HA worker count from `dhall/cluster/resources.dhall` |

The report-card knobs parameterize their canonical measurement stanzas. They
are not ProductRow registry budgets and cannot mint ProductRow completion.
Supervised ProductRows execute their registered `10`-, `15`-, or `40`-epoch schedule;
traditional RL ProductRows execute the aggregate environment-transition count
derived by `JitML.RL.ProductBudget`, including vector-environment and indivisible
rollout/episode granularity.
