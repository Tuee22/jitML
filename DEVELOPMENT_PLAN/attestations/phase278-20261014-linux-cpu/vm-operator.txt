Dedicated jitML validation VM, created 2026-10-14.
QEMU/KVM guest inside the existing Ubuntu WSL2 distribution.
Ubuntu 24.04 LTS official release cloud image, verified SHA256.
Digest in image-checksum.txt; host evidence in provision-evidence.txt.

Fixed guest RAM 48 GiB, QEMU memory cap 50 GiB, swap disabled.
16 vCPU; host CPU model; affinity/allowed CPUs 0-15; CPU quota 1600%.
300 GiB maximum sparse QCOW2 guest disk.
CPU affinity contains VM work within selected WSL CPUs; CPUs are shared with
other Windows/WSL processes. Global WSL settings have not been changed.
SSH is exposed only on 127.0.0.1:2222. Docker runs independently in the guest.

PowerShell invocation prefix: wsl -d Ubuntu -u root --
Append /var/lib/jitml-validation/ssh hostname for guest hostname.
Append /var/lib/jitml-validation/sync-repo to copy current source.
Append /var/lib/jitml-validation/run-script LOCAL_WSL_SCRIPT_PATH for a
multiline guest script. Scripts are transferred to guest bash via stdin.
Append systemctl status jitml-validation.service for VM service status.
Append tail -n 80 /var/lib/jitml-validation/console.log for guest console.

Source destination is /home/ubuntu/jitML and is checked with realpath.
sync-repo copies source, excludes .git/generated caches, restores executable
modes from the index, and converts tracked i/lf files to LF in the guest.
It keeps guest task-only files. The source filesystem is not mounted in guest.

WSL requires an active client to stay alive. A hidden wsl.exe process maintains
that client, with its initial Windows PID recorded in windows-keepalive.pid.
After a Windows restart, recreate that hidden client and start the VM service.
The service is enabled, so it starts when the WSL distribution starts.
Use guest sudo poweroff for a graceful shutdown.
