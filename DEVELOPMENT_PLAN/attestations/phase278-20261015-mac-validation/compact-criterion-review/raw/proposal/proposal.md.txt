## Recommendation and claim

Keep the documented compact graphs, data selections and terminating per-run budgets. Adopt a prospectively versioned **compact-recipe predictive-learning criterion**, with the existing learning-signal tests as its baseline controls, an exact paired improvement over each run's own initialization, and the existing stronger product floors as additional unchanged restrictions. Validate the criterion using five actual predeclared training seeds per recipe and lane. This is a proposal for a limited, testable product claim, not an assertion that the criterion or training evidence is already complete.

The proposed qualifying statement is:

> Under this versioned compact recipe and its unchanged fixed per-run budget, five predeclared training runs were executed. A majority of those runs both improved held-out predictive performance over their own initial model and beat the independently specified constant/uniform-random controls. The five-run median also cleared the unchanged product floor. The predetermined served run independently met the existing publication checks, and its metric was recomputed from its exact admitted artifact. This establishes the stated compact-recipe benchmark result; it does not establish published-model parity, population generalization, or statistical confidence against every input-independent predictor.

Paired improvement is recommended because it makes the word **learning** directly falsifiable: an unchanged initial model cannot pass it, even if that initialization happens to beat a constant or uniform random predictor. The zero-improvement boundary is dictated by this claim rather than calibrated to an observed trained score. It adds no arbitrary accuracy margin and weakens no existing floor. If the intended claim were only “nontrivial prediction after a training process ran,” the existing guards could define that narrower descriptive criterion without paired improvement; that is a weaker claim than this recommendation.

No additional fixed minimum effect size follows from statistics alone. An application-utility claim, specified accuracy guarantee, or published-architecture parity would need an independently chosen utility margin or matching benchmark recipe. Those are additional claims, not requirements that can be invented from papers about different models. This proposal chooses the explicit finite-benchmark improvement claim above.

## Exact semantics

Freeze before new qualifying training: criterion version, graph/runtime recipe, dataset SHA and deterministic train/selection/final-evaluation membership, target/feature transforms fitted only on training data, semantic class count, evaluation count/order, five distinct training seeds, unchanged per-run schedule, selected lane, and the complete expected attempt inventory. Do not pick seeds or bounds after examining candidate scores. One independently reviewed record must state the claim, algebra, historical-floor provenance, and why the comparison models match the claim.

For classification seed `s`, evaluate exact initial and final graph parameters through the same serving interpreter/transforms on the same held-out examples:

```
n = held-out example count; C = semantic class count
M = largest held-out label count
B = min{k in [0..n+1] : P[Binomial(n,1/C) >= k] <= 1/3000}
K_initial(s), K_final(s) = exact integer correct counts
signal(s) = K_final(s) >= max(M+1, B)
improvement(s) = K_final(s) > K_initial(s)
```

`B=n+1` intentionally fails an evaluation too small to attain the critical count. The binomial decision remains exact integer arithmetic; no rounded accuracy or parity tolerance can turn a failing count into a pass. All labels, class bounds, predictions, vector widths and measurements must be valid/finite. The present implementation's majority condition rejects every constant classifier on this evaluation set. It does not prove arbitrary feature dependence.

For regression, use the current positive finite target scale and the actual finite binary64 target/prediction vectors, interpreted as exact rationals:

```
y_mean = exact mean of the held-out targets
SST = sum((target - y_mean)^2) > 0
SSE_initial(s) = sum((initial_prediction - target)^2)
SSE_final(s) = sum((final_prediction - target)^2)
signal(s) = SSE_final(s) < SST
improvement(s) = SSE_final(s) < SSE_initial(s)
```

Use strict comparisons with no epsilon. A non-finite initial predictor is an invalid run, not an infinite-error baseline that makes every final model “improve.” The positive scale cancels in comparisons but must remain bound to the same training-fitted standardization. Constant targets fail closed. The `SSE<SST` boundary is the empirical positive-R² definition, not an RMSE tolerance or a population inference. It excludes every constant prediction vector because the held-out mean minimizes constant squared error. [Official R² definition](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.r2_score.html).

Retain **all five** finite complete runs, including below-bar runs, in the cohort. A missing/incomplete/non-finite run fails the cohort; do not replace its seed or extend its budget. Require at least three of five seeds to satisfy **both** `signal(s)` and `improvement(s)`; separate medians can otherwise succeed on different subsets. Also require the five-run median final accuracy/RMSE to clear the unchanged current row floor. These predicates supply a median-of-five learning result while preserving the existing median threshold.

Keep current per-run publication eligibility unchanged, and add paired improvement to the predetermined served run if this contract governs its claimed learning qualification. In particular, median success cannot publish a below-bar run. Choose the served run prospectively, for example the current canonical seed; do not select the best seed by final test score. Below-bar members remain bound run evidence, never forged admitted completed checkpoints. A cohort may therefore satisfy its descriptive median while its predetermined publication fails; the ProductRow still fails.

The historical classification restrictions remain the exact existing code comparisons (nominal floors approximately `0.90,0.90,0.30,0.81,0.81,0.25,0.20,0.25,0.04,0.008` in current table order), and regression retains standardized `RMSE<=1.0`. Do not replace exact current binary64 comparison behavior with rounded table numbers. Acceptance is the conjunction of the independent rule, real execution/provenance, seed evidence, and these restrictions. A restrictive historical constraint cannot make a model failing the independent rule pass. Its historical origin nevertheless remains post-hoc/unproven; the conjunction does not make that origin external.

## Statistical scope and limits

The binomial reference is specifically independent uniform guessing over `C` labels; its success probability is `1/C` even when the fixed label histogram is imbalanced. Its exact tail follows the [NIST binomial distribution](https://www.itl.nist.gov/div898/handbook/eda/section3/eda366i.htm). It is not a test of all input-independent classifiers. For example, on 600/400 binary labels, a predictor choosing the majority class except at one uniformly chosen position beats the majority by one with probability `0.4`, while its 601/1000 score clears the uniform-guessing tail. The strict majority rule rejects constants; it does not extend the binomial null to this predictor. The accompanying arithmetic script demonstrates this limitation without running any model.

The existing `1/3000` comment budgets 0.01 across ten classification rows × three lanes for **one run each**. Five seeds yield 150 planned comparisons: the simple upper bound becomes `150/3000=0.05`, for that uniform null and fixed family. This union bound does not require independence between comparisons; each individual binomial null does require its stated guessing assumptions. [NIST's general Bonferroni inequality](https://www.itl.nist.gov/div898/handbook/prc/section4/prc473.htm). Do not claim 0.01 across five seeds, include regression in that confidence statement, or claim repeated adaptive attempts are covered. Keeping the same alpha preserves the current guard; an overall 0.01 five-seed claim would require a stricter new alpha and a different contract.

Paired accuracy/SSE improvement here is descriptive and exact on the pinned examples. No significance or population-confidence claim is assigned to it or to strict positive R². The same data reused across five training seeds do not become five independent population samples. The current deterministic prefixes and previously examined benchmark data do not become virgin test samples after a policy version change. Keep an attempt ledger and validation-only model selection. [Cawley and Talbot's primary study](https://www.jmlr.org/papers/v11/cawley10a.html) explains why optimizing a finite evaluation criterion can bias reported performance. Neither a version token nor a new seed erases that issue.

An exact label-permutation test would address a broader exchangeability null than uniform guessing; it would still need assumptions, an attempt family and independence from adaptive selection. It is not necessary for the explicitly limited empirical claim proposed here, and would not by itself establish real input dependence or population generalization. Phase 279's behavioral detector remains its own later obligation. Phase 278 must not wait backward on that feature or pretend its guard already implements it.

## Is the initial comparison available honestly?

Yes, enough exact material is already available **at the producer boundary** to reconstruct the initial serving computation, not merely a hash:

- `SlRunMetrics.slmInitialWeights` captures graph-ordered initial classification parameters before updates. `TrainingExecution.trainingMetricsFor` encodes those F64 values into exact JMW1 bytes, alongside final `LayerGraphMetadata` and input/output transforms.
- `SupervisedPublishRun` carries initial JMW1 bytes, final JMW1 bytes, graph metadata, runtime transforms and held-out examples. JMW1 is little-endian IEEE-754 F64, so decoding does not invent Float32-rounded starting weights.
- Current `LayerNode` has operator, shape, mode, activation and optional flat parameters; there is no additional BatchNorm running-state field outside those values. `replaceGraphParameterVector` changes only parameters. The final graph descriptor can reconstruct this static recipe and inject initial bytes. Runtime transforms fitted from training data must be identical for initial and final evaluation.
- Housing currently reconstructs `mlpInit exactShape exactSeed` in `finishCaliforniaHousingTraining`, rather than returning that vector from its optimizer loop. This is a concrete deterministic reconstruction, not a stored performance observation, but the new baseline witness should preferably come directly from the trainer-owned initial parameters. Document the distinction until changed.

The smallest robust producer change is to capture/hash the initial graph descriptor **before the first update**, preserve its actual initial parameter bytes, and require descriptor equality with the final recipe. No untrained artifact needs completion or Store admission. After real final Store admission, reconstruct this comparison graph separately and run the **same exact serving interpreter** with its initial bytes and identical runtime transforms. Final predictions must continue to come from the actual admitted final artifact. Avoid a validator that requires the baseline's weight SHA to equal the final payload's final SHA: the baseline is a named comparison computation, not an admitted final model. Do not weaken `admitLocalCheckpointAt`, completion validation or public checkpoint eligibility to make an untrained model pass.

Current `RawTrainingRuntimeArtifact` contains initial and final JMW1 bytes, but its payload stores only final graph metadata; published payloads commit initial SHA rather than prove a separately captured initial graph. Existing artifact material is therefore suitable for a prototype/reconstruction, but a read-time learning qualification should retain the initial comparison descriptor/bytes and bind their hashes explicitly. Do not claim every old admitted checkpoint already proves this new baseline.
