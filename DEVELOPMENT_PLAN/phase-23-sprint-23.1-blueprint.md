# jitML Sprint 23.1 — Typed Layer IR + Reverse-Mode Autodiff: implementation blueprint

## 0. The one reconciliation everything hangs on

There is a hard, non-negotiable conflict between input (A) and input (B) that the blueprint resolves up front, because every later decision depends on it:

- **(A) per-node specs** require rich, heterogeneous parameters: Conv a `[C_out,C_in,Kh,Kw]` kernel; MHA four `d_model²` matrices `W_Q/W_K/W_V/W_O` + biases; GeGLU three matrices `W_a/W_b/W_2`; every norm a `γ/β` pair. None of these fit a single `MlpParams`.
- **(B) + the checkpoint contract** (verified: `RuntimeArtifact.deriveLayerSlices` 1086-1095; `Architecture.hs:1739` packs `AttentionState` as one `mlpParamsToFlat`) forces **every serialized SL operator to be exactly one `MlpParams = W1,b1,W2,b2`**, byte-frozen against product-row checkpoints on disk.

**Resolution — a two-tier IR, one type, two parameter regimes, with a version wall between them:**

1. **Tier-1 (served/trained/serialized SL graph).** The unified typed graph the SL path executes. Its parameterized nodes keep the coarse `MlpParams` payload **byte-for-byte** (attention's QKV stays the fused `(w,h,3w)` projection it already is). Only **param-neutral** correctness fixes from (A) land here in 23.1 (attention residual add; dropping the spurious outer `tanh`/`SiLU`; any VJP correction that does not change parameter count).
2. **Tier-2 (verified autodiff node library).** The correct Conv2D/Conv3D, Max/Avg/GlobalAvgPool, Batch/Layer/GroupNorm, MHA-with-W_O, PatchEmbed, GeGLU, Residual/BasicBlock/Bottleneck nodes with (A)'s exact forward/backward, expressed in the **same** `LayerNode` type via an ordered named-tensor parameter payload, and gated by finite-difference tests in `jitml-unit`. These nodes are **not** admitted into the frozen SL serialization in 23.1 — wiring them into the served path + checkpoint requires a format version bump and is **23.2**.

The single `LayerNode` type subsumes both: the Tier-1 `MlpParams` operators are the degenerate case whose named tensors are exactly `[("W1",…),("b1",…),("W2",…),("b2",…)]`, so `graphParameterVector` flattens identically and the slice contract is unchanged; Tier-2 nodes carry more named tensors and are simply never emitted into a V2 supervised manifest. **This is the honest way to deliver "Typed Layer IR + correct autodiff" without breaking checkpoint admission or moving convergence bars — the two are separated by a format wall, not conflated.**

Surface this decision to the sprint owner before step 3 (§6). The only alternative is a checkpoint format v-bump inside 23.1, which enlarges scope and perturbs the frozen 24.2 bars.

## 1. The enriched `LayerGraph` representation (reconciled, one design)

All changes in `src/JitML/Numerics/LayerGraph.hs` unless noted.

### 1.1 Shapes
`TensorShape` is already `[Int]`; stop collapsing it. Add `tensorShapeRank`, token/channel accessors, and let a node's input/output be rank-2 `[tokens, channels]` or rank-3/4 `[C,H,W]`/`[C,D,H,W]`. The value threaded by the runner becomes the existing `BatchRep` (`FlatBatch | TokenBatch`), not a bare `Vector Double` — this is the single most load-bearing representational change and is shared with (B)'s token-aware requirement. `mkAffineLayer`'s collapse to `[inputWidth]` (237-238) and `mkIdentityLayer`'s `in==out` copy (244) are the two constructors that erase structure today; both are replaced by shape-computing smart constructors.

### 1.2 Parameter payload — one ordered named-tensor model
Replace the single `LayerParameters {layerWeights, layerBias}` with:

```
data ParamTensor  = ParamTensor { ptName :: !Text, ptShape :: !TensorShape, ptData :: !(Vector Double) }
newtype LayerParams = LayerParams { lpTensors :: [ParamTensor] }   -- ordered
```

- `graphParameterVector` / `replaceGraphParameterVector` / `flattenLayerGraphGradient` (336-396, 701-708) walk `lpTensors` generically → they keep working for **any** node.
- **Tier-1 invariant:** an `MlpParams` operator's `lpTensors` is exactly `[W1,b1,W2,b2]` in that order, so the flattened vector equals `mlpParamsToFlat` and the frozen slice names/offsets are unchanged. Provide `mlpParamsToTensors :: MlpParams -> LayerParams` and its inverse; keep `MlpParams` as the ergonomic Tier-1 payload and convert at the IR boundary.
- Tier-2 nodes list their real tensors (conv: `["kernel","bias"]`; MHA: `["Wq","Wk","Wv","Wo","bq","bk","bv","bo"]`; GeGLU: `["Wa","Wb","W2","ba","bb","b2"]`; norm: `["gamma","beta"]`).

Move `PatchRuntime`, `ImageGeometry`, and the attention/token/layernorm forward tapes out of `Architecture.hs` (255-291) into `LayerGraph` (or a shared `LayerGraph.Operators`) so the IR is the single home of topology + runtime state.

### 1.4 Tape enrichment
`LayerForward` (161-167) gains optional per-node backward state, threaded by `runLayerNode`/`backwardLayerNode`:
- `layerForwardPoolArgmax :: Maybe (Vector Int)` — MaxPool switches (deterministic lowest-flat-index tie-break; store, do not recompute).

## 2. Correct per-node forward+backward (summary + cross-node inconsistencies)

Per-node math is (A) verbatim; the sketches there are directly implementable. Condensed contract per kind:

- **Conv (2D/3D, one N-D path):** cross-correlation with zero-padding; `H_out=(H+2P−K)/S+1`. Backward = three transposed linear maps: `dK = dY·Colᵀ`, `db = row-sums`, `dX = col2im(Wᵀ·dY)` via `VU.accum (+)` (overlap accumulates). Conv3D is the same code with a depth axis. **Conv3D is dead today** — this per-node FD test is its only correctness guard.
- **Pool:** `MaxPool` routes `dX[argmax] += dY` (scatter-add; overlap sums); `AvgPool` scatters `dY/A` (divisor `A` follows `count_include_pad`); `GlobalAvgPool` reduces per channel → output `[C]`, `dX[c,·]=dY[c]/(H·W)`. All parameterless (`layerGradientParameters == Nothing`).
- **Norm (Layer/Group/Batch):** identical VJP skeleton `dx = r·(ĝ − mean(ĝ) − x̂·mean(ĝ·x̂))` with reductions taken over the correct axis set (LayerNorm: whole feature row; GroupNorm: within group; BatchNorm: across batch). `dγ=Σ g·x̂`, `dβ=Σ g`. BatchNorm additionally needs a **batched** signature and a train/inference split (inference = frozen affine, no coupling).
- **MHA:** reshape `[S,d_model]`, per-head scaled-dot-product softmax, concat, output proj, **residual** `Y=X+O`. Backward is the standard softmax Jacobian `diag(p)−ppᵀ` chain; `dx_s = dY_s + W_QᵀdQ_s + W_KᵀdK_s + W_VᵀdV_s`.
- **PatchEmbed:** im2col patchify → shared projection (+ optional learned pos-emb); backward `dW=Σ dE_n p_nᵀ`, `dX = col2im scatter`.
- **GeGLU:** `y = W_2·(a ⊙ GELU(g)) + b_2`; exact-erf GELU and its exact derivative `Φ(u)+u·φ(u)`.
- **Residual/BasicBlock/Bottleneck:** typed `Shortcut`; block = ordered `ConvStage` list; final activation after the add; identity/projection explicit.

### Cross-node inconsistencies to flag (must be resolved consistently, not per-node)

1. **Silent width-mismatch collapse** appears identically in Residual, BasicBlock, Bottleneck (`length input == length activated` guard). Fix once via the shared `Shortcut` type: `IdentityShortcut` errors on `d_in≠d_out`; `ProjectionShortcut` carries `W_s,b_s`. Projection is **mandatory** for Bottleneck (channels always change) and ResNet downsampling.
2. **BatchNorm inside blocks is ill-posed.** BasicBlock/Bottleneck specs correctly say block-internal norm must be **LayerNorm/GroupNorm** (or frozen-BN running-stats), never per-sample `normalizeOne`. Standardize: `BlockStage` norm defaults to LayerNorm/GroupNorm; BatchNorm-as-executed-op is a separate batched node, not a block sub-stage.
3. **Spurious outer nonlinearity.** MHA, PatchEmbed, GeGLU currently sit under a node `tanh`/`SiLU` (`Architecture.hs`). The intrinsic nonlinearity is softmax/GELU; the node activation **must** be `LinearActivation`. Consistent removal across all three; also update `graphPlansForFamily` to stop setting `tanh` on these nodes.
4. **Residual scale `s`** is baked into the `LayerKind Double` in all three block kinds, is absent from the parameter vector, and is **never FD-tested**. Decide once: fixed hyperparameter (documented, excluded from param vector) vs learnable `LayerScale` (`∂L/∂s=⟨d,a⟩`, added to the vector and FD-swept). Recommend fixed for 23.1 to avoid touching seed layout.
5. **GELU form policy** must be global: pick exact-erf (add `Numeric.erf` or an A-S 7.1.26-grade rational) or tanh-approx, and the backward derivative must match the chosen forward form exactly. Recommend exact-erf.
6. **BatchNorm biased-var forward vs unbiased-var running update** — classic mismatch; keep biased `/m` in normalize, `m/(m−1)` only in the running-var EMA.
7. **PatchEmbed emitting N>1 tokens** is the largest blast radius: it breaks the implicit `S=1` assumption every downstream node relies on. Attention/norm/GeGLU/mean-pool must all operate over the token axis — which is exactly why §1.1's `BatchRep`/`TokenBatch` threading is a prerequisite, not an afterthought.

## 3. Finite-difference test additions (`test/unit/Main.hs`)

The existing harness (`maxFiniteDifferenceError`/`finiteDifferenceAt`, LayerGraph.hs:382-396,710-727) perturbs **only** `graphParameterVector`; pool/norm gradients are therefore never exercised today (this is how the bugs survived). Add:

**New harness primitive (required first):**
```
maxInputFiniteDifferenceError :: Double -> LayerGraph -> Input -> Target -> Vector Double -> Either Text Double
-- for each input coord i: central diff of layerGraphLoss vs layerGraphInputGradient ! i
```

**Per-node cases (param-FD where params exist, input-FD always):** central diff `eps=1e-6`, `tol≈1e-6` absolute (tighten to `1e-9` for globally-linear ops: AvgPool/GlobalAvgPool/PatchEmbed/Conv-with-Linear). **Smooth activations only (Linear/Tanh, never ReLU** — kink at 0 makes FD meaningless; ReLU gating unit-tested separately).

- **Conv2D** (cIn2,cOut3,4×4,k3,s1,p1): param-FD over 54 weights+3 bias; input-FD over 32; adjoint cross-check `⟨dY,conv X⟩ = ⟨dX,X⟩ = ⟨dK,K⟩`.
- **Conv3D** (cIn2,cOut2,3³,k2,s1,p0): as above; assert output length invariants (this is Conv3D's only guard).
- **MaxPool** (1×4×4,k2s2): assert `layerGradientParameters==Nothing`; input-FD with strictly-distinct in-window values + **tie-flip guard** `eps < ½·min-gap`; overlap case (s1) confirms shared-argmax accumulation.
- **AvgPool** (2×4×4): non-overlap, overlap-accumulation, and padding+`count_include_pad` True/False (divisor differs at edges; padded positions get exactly 0).
- **GlobalAvgPool** (3×2×2): asymmetric target → **channel-separation assertion** (each channel's inputs get `(Y[c]−t[c])/(H·W)`; the test that fails on current code); block-diagonal Jacobian check.
- **LayerNorm / GroupNorm** (N=6; GroupNorm G=3, plus a P>1 variant): param-FD over `γ,β`; input-FD confirming the coupled Jacobian; GroupNorm cross-group entries exactly 0; divisibility guard `C mod G ≠ 0 ⟹ Left`.
- **BatchNorm** (C=4, B=5, TrainingMode): **batched full-batch loss** (mandatory — per-sample loss hides the coupling); input-FD (perturbing `X[b][k]` moves all samples at feature k), param-FD accumulates across batch, InferenceMode variant (no coupling), B=1 guard.
- **MHA** (S3,d4,H2): param+input FD via `replaceGraphParameterVector`; near-degenerate softmax row; residual check (`W_O≈0 ⟹ dX→dY`); H=1 must match eager `attentionBackward` numbers.
- **PatchEmbed** (1×4×4,P2,d3): shared-W accumulation over N patches; col2im input routing; overlapping (s1) variant.
- **GeGLU** (in4,ff6,out3): gate values spanning `g<0,≈0,>0` (GELU' non-monotone dip); separate-branch routing (`b_a` value-only, `b_b` gate-only).
- **Residual / BasicBlock / Bottleneck:** identity + projection variants pass both sweeps; `isLeft` on `d_in≠d_out` identity, on non-composing stage shapes; BasicBlock adds a **broken-normBwd regression guard** (dropping the `−x̂·mean(ĝx̂)` term must push param-FD past tol).

**Full-graph shaped tests:** assemble a small **ResNet-shaped** graph (conv stem → 2 BasicBlocks with one projection downsample → GlobalAvgPool → Dense) and a small **ViT-shaped** graph (PatchEmbed N=4 → LayerNorm → MHA(residual) → LayerNorm → GeGLU → MeanPool → Dense). Run param-FD and input-FD end-to-end through the composed `LayerGraph` — this is the integration guard that the token-axis threading and multi-node backward compose correctly.

Widths flow via `mapAccumL` tracking executed channel/token width, giving a build-time shape contract.

Repoint `projectTrainedArchitectureRuntime`/`canonicalClassificationRuntimeContract`/`projectRuntimeLayer` (1042-1244) to walk `layerGraphNodes archGraph`; `RawRuntimeLayer` set/order/shapes are identical, so `supervisedRuntimeVirtualSlices`/`parameterCount`/blob bytes are byte-stable and existing checkpoints admit. `RuntimeArtifact.hs` derivation is **unchanged** (verify only).

6. **Param-neutral correctness fixes that land in Tier-1 now:** attention **residual add** (`Y=X+O`, the deferred "23.1 residual correction" at `Architecture.hs:2385-2388`, free — no new params) and **dropping spurious node activations** on attention/patch/geglu. 7. **Mlp.hs unchanged surface.** `mlpLayerGraph` stays the canonical two-`DenseLayer` lowering; hoist a shared `denseMlpNodes :: MlpParams -> [LayerNode]` that both `Mlp.hs` and each Tier-1 affine operator call — one lowering, one autodiff tape.

## 5. Validation plan + convergence go/no-go

- **`jitml-backends`** — the oneDNN/Metal/cuBLAS operator-node reconstruction from flat slices is the **23.2** seam; 23.1 only keeps the Dense base case green.

### 5.2 Convergence go/no-go (from C)
**GO with one blocker: `cifar10-vit`.** Effective bar 0.25, historical proxy 0.218; the real self-attention path is more data-hungry and removes the mixer's optimization crutch — median(k=5) will straddle 0.25. Conv rows (resnet20/56, cifar100-wrn) are *helped* by real inductive bias; MLP rows clear comfortably.

**Mitigations 23.1 must land (all honest — respect `slack>0` and real published targets):**
- **A. LR warmup + cosine decay** — none exists today (only a flat scalar `learningRateOverride`); highest leverage; fixes deep-ResNet stall and ViT instability. Do first.
- **B. Principled init + zero-init last-norm-γ per residual branch** — the honest analog of the proxy's hand-tuned `residualScale`; makes deep real ResNets trainable in few steps.
- **C/D. More real CIFAR data (2000→5-10k) and more epochs (5→10-15)** for the vision rows — policy choices, not literature constraints; biggest lever for ViT.
- **E. Only light CIFAR aug, paired with more epochs** — flag: it is *not* currently staged (grep-confirmed absent in SL); heavy aug under a 5-epoch cap hurts.
- **F. Bar/slack re-anchoring — last resort, off-table** (bars frozen for 24.2).

**Go/no-go action:** run a **dry median(k=5) for cifar10-vit inside 23.1** under the A+B+C+D regime. If it does not clear 0.25 honestly, that is the 24.2 no-go and must be surfaced now, not at the gate.

**Realness holes to resolve now (anti-fabrication, not convergence):** `tiny-imagenet-resnet50` effective bar **0.00** and `cifar100-wide-resnet` **0.04** pass at any accuracy (an untrained net clears them). Decide explicitly: raise the effective bar above the random floor, or reclassify as compute/plumbing-demo rows. Also verify `fashion-mnist-resnet`'s 3e-3 LR against a real ResNet (add warmup or lower).

## 6. Ordered, dependency-aware task list + scope

**Critical path (strictly ordered):**
1. **IR enrichment (additive).** `ParamTensor`/`LayerParams`, token-aware `TensorShape`/`BatchRep` threading, the `LayerKind` union + spec records, smart constructors. Keep the fine single-affine path + Mlp.hs/RL/AlphaZero green. *(risky: touches the core type; land behind conversion shims.)*
2. **`maxInputFiniteDifferenceError` harness** + Tier-2 node forward/backward from (A), each landed with its §3 FD test. **Parallelizable across node kinds** once step 1 is in — Conv, Pool, Norm, MHA, PatchEmbed, GeGLU, Residual/BasicBlock/Bottleneck are independent; assign per engineer. Conv2D/Conv3D share one N-D path (do together). *(This is the bulk of the "correct autodiff" deliverable and the main verification value.)*
3. **Capture golden anchors** (flatten order, seed, checkpoint admission) — before any Architecture change.
4. **Move operator bodies** (attention/norm/tokenmix/patch/meanpool/deviceGradientStep + tapes) into `LayerGraph` on `BatchRep`, byte-identical, behind a shim. *(risky: bit-identity requirement.)*
5. **Rewrite `graphPlansForFamily`** into the single seeded operator builder; add `archGraph`; keep `archLayers`/`archLayerGraph` as *derived* accessors asserting `derived == old`.
6. **Switch initializer/forward/backward/predict/training** onto `archGraph`/`TrainingGraph`; run all three SL lanes for bit-identity; land the **param-neutral attention residual + drop-tanh** fix (§4.6).
7. **Repoint serialization** to the graph; prove slice/parameterCount/blob byte-stability with the golden diff.
8. **Land training-regime work (A+B warmup/init)** and run the **cifar10-vit dry median(k=5)** go/no-go.
9. **Resolve feature-parity rescope** (§4.10) + realness-hole posture (§5.2); update `sl-canonicals`, `ProductExperimentExactness`, `SupervisedTrainingSeed`, `integration` tests.
10. **Delete** decorative graph, `LayerSpec`, `LayerState`, `GraphLayerPlan`, stencil family, derived-accessor shims, collapsed seed arm. Full lane + golden + FD green.

**Deferred to 23.2 (explicitly out of 23.1 scope):** admitting Tier-2 conv/norm/geglu nodes into the served path + checkpoint (needs format v-bump); `rebuildLayerGraph`/`LayerGraphOneDnn`/`LayerGraphCheckpoint` operator-node reconstruction from flat slices; `jitml-backends` operator coverage; executed-path `W_O`/norm-`γβ`.

**Honest scope estimate.** This is a **large** sprint, realistically the upper end of a single sprint or a 1.5-sprint effort:
- Step 2 (Tier-2 node library + FD tests) is the largest single chunk — ~9 node families × (forward+backward+2 FD sweeps) — but it *parallelizes cleanly* and is low-risk (pure, finite-diff-gated).
- Steps 4-7 (the unification/bit-identity move) are lower volume but **highest risk**: the byte-stability and bit-identity requirements mean any silent numeric drift fails the golden/lane gates, and the token-axis (`S>1`) contract change has the widest blast radius.

# Sprint 23.1 — Graph Unification Design: making the trained/served SL path execute the one typed `LayerGraph`

## 1. The actual state and the core reconciliation problem

Today `ArchitectureSpec` (Architecture.hs:154–160) carries **two** parallel topologies:

- **Executed** — `archLayers :: [LayerSpec]` (199–236). `initialiseLayers` (1822–1867) turns each `LayerSpec` into a `LayerState` (238–246) that carries a *real 2‑layer MLP* `MlpParams` (`W1,b1,W2,b2`) + `AdamState`. Training (`trainEpoch`/`trainBatch`/`forwardWithTapes`/`backwardAll`, 1742–2154) and serving (`forwardOnly`/`predictArchitectureWithDevice`/`accuracy…`/`crossEntropy…`) run these states over a `BatchRep` (`FlatBatch | TokenBatch`) with genuine token structure, real softmax QKV attention (`attentionForward`/`attentionBackward`), real LayerNorm, token‑mixing MLPs, patch extraction, and mean‑pool. Checkpoint bytes come from here.
- **Decorative** — `archLayerGraph :: LayerGraph.LayerGraph`, built by `graphPlansForFamily`/`graphNodes` (463–616). Its parameterized nodes are **single affines** (`W [o×i] + b`) over a **flat vector only**, with *fixed, untrained* input stencils standing in for Conv/PatchEmbed/GeGLU/attention (LayerGraph.hs `parameterizedInputForward`, 537–576), seeded by node index and **never trained, never executed**. Its only live jobs are: feature‑parity claims (`architectureImplementedFeatures`/`validateArchitectureFeatureParity`, 681–699), one arm of `architectureSeedHeadroomForProblem` (428–443), and node‑kind metadata.

The two are **numerically inequivalent**, not just duplicated: even `DenseFamily` differs — executed is `inputs→hidden→outputs` (a hidden layer), decorative is a single `inputs→outputs` affine. The decorative graph "implements" BatchNorm/GroupNorm/Dropout/GeGLU/Bottleneck only *nominally* (a `LayerKind` tag + a cheap stencil); the executed path does not run those ops at all. So "make the executed path run the one typed graph" is a representational redesign, and the binding constraint is the **checkpoint Flat‑slice byte layout**, which is committed to the executed 2‑layer‑MLP‑per‑layer convention.

**The checkpoint fixed point (must not move).** The V2 supervised physical tensor `supervised.weights` has shape `[parameterCount]` and is the JMW1 encoding of `architectureLayerWeights` (1730–1740) = `concatMap mlpParamsToFlat` over `LayerState`s = per layer `[W1,b1,W2,b2]`. The `FlatWeightLayout` virtual slices (`RuntimeArtifact.supervisedRuntimeVirtualSlices`, RuntimeArtifact.hs:1082–1115) are derived per `RuntimeLayer` as exactly `("W1",[h,i]),("b1",[h]),("W2",[o,h]),("b2",[o])`, cumulative offsets in execution order; `parameterCount` sums `runtimeMlpParameterCount` over layers (606–612). `Checkpoint.Format.validateSupervisedManifestShapeLayout` (1720–1728) rejects any manifest whose layout ≠ these graph‑ordered slices, and existing frozen product‑row checkpoints on disk carry these exact names/shapes/order. **Any unification that renames slices, regroups them, changes count, or reorders bytes breaks admission of existing checkpoints.**

**Decision that resolves the tension:** keep the *serialization boundary* at **coarse MLP‑operator granularity** (one `RuntimeLayer`/slice group per SL operator, W1..b2 naming unchanged), and make the **one typed graph the SL path executes** an *enriched `LayerGraph` whose parameterized nodes are those same operators*, each carrying a real `MlpParams` payload (plus `AdamState` during training) and the correct structural attributes. This deletes the decorative single‑affine graph, eliminates the `LayerSpec`/`LayerState` split, preserves executed numerics bit‑for‑bit (so convergence bars and product‑row budgets do not move), and preserves checkpoint bytes exactly. The **fine single‑affine `LayerGraph`** that Mlp.hs already produces (`mlpLayerGraph`, two Dense nodes) stays as the sub‑lowering / autodiff‑and‑oneDNN IR beneath each MLP operator — shared unchanged with RL/AlphaZero and Phase 23.2.

In short: **one typed operator graph is the source of truth; execution, serialization, feature claims, seed headroom, and architecture metadata all become projections of it; the fine `LayerGraph`+autodiff tape is the per‑operator numeric kernel it lowers to.**

## 2. The unified representation

Replace the `archLayers`/`archLayerGraph` pair with a single field on `ArchitectureSpec`:

- `archGraph :: LayerGraph.LayerGraph` — an *enriched* graph whose nodes are the executed operators, in execution order.

To carry the executed operators faithfully, `LayerGraph.LayerNode` must be enriched (this is the "correctly‑parameterized representation"):

1. **Token‑aware shapes.** Generalize `TensorShape` usage so a node's input/output can be rank‑2 `[tokens, channels]`, not only flat `[width]`. `tensorShapeWidth` already collapses to a product; add `tensorShapeRank`/token accessors. The graph value model threaded by the runner becomes the existing `BatchRep` (flat vs token) rather than a bare `Vector Double`.
2. **Operator‑bearing parameters.** A parameterized node carries the operator's `MlpParams` (not a bare `LayerParameters` single matrix), so the flattening `graphParameterVector` over `archGraph` yields exactly `architectureLayerWeights` order. Concretely, either (a) generalize `LayerParameters` to an `MlpParams`‑shaped payload, or (b) add `layerNodeOperator :: Maybe MlpParams` alongside the existing `layerParameters` and let the coarse operators use it. Recommend (a): make the graph's parameter payload the MLP block, and have the *fine* Dense node be the degenerate `h`-less case reused by `mlpLayerGraph`.
3. **The operator `LayerKind` vocabulary** becomes the union that names what actually executes — i.e., the current `LayerState` constructors re‑expressed as graph kinds: `DenseMlp`, `ResidualMlp Double`, `TokenMixMlp Int`, `PatchStem PatchRuntime`, `Attention`, `LayerNorm`, `MeanPool`. `PatchRuntime`, `ImageGeometry`, the attention/token/layernorm tapes (currently Architecture‑local, 255–291) move into `LayerGraph` (or a shared `LayerGraph.Operators` module) so the graph is the single home of both topology and runtime state.
4. **Training state.** During training the node additionally carries `AdamState`. Model this as a parallel `[Maybe AdamState]` keyed by node, or an enriched "trainable graph" wrapper (`TrainingGraph = LayerGraph + per-node optimizer state`). This replaces `[LayerState]` and `ExactArchitectureTraining.exactTrainingStates`.

The decorative constructs deleted: `GraphLayerPlan`, `graphPlansForFamily`'s single‑affine emission, `graphNodes`, `residualStem`/`basicBlock`/`bottleneckBlock`/`wideBasicBlock`/`mixerGraphBlock`/`residualHead` (463–578), the whole `parameterizedInputForward`/`parameterizedInputBackward` stencil family (LayerGraph.hs 537–628) *as the SL model* (kept only if reused for a real op; otherwise removed), and `fallbackIdentity`.

## 3. How `graphPlansForFamily` builds correctly‑parameterized nodes

`graphPlansForFamily` is rewritten to emit the **one** operator list per family — it becomes the single successor to *both* `layersForFamily` (367–420) and the decorative `graphPlansForFamily` (463–518). It is sized from the same `ClassifierConfig`‑derived dimensions already in `architectureSpecForProblem` (`inputs`, `outputs = clfClasses+1`, `latent`, `wideLatent`, `geometry`, patch sides), and it emits nodes with **fully resolved shapes and parameters**, not placeholders:

- For each family, emit exactly the operator sequence `layersForFamily` produces today (so numerics/topology are unchanged), but as typed nodes:
  - `DenseSpec i h o` → a `DenseMlp` node with `layerInputShape=[i]`, `layerOutputShape=[o]`, MLP shape `(i,h,o)`.
  - `ResidualSpec w h scale` → `ResidualMlp scale` node, shape `(w,h,w)`, token‑or‑flat by position.
  - `LayerNormSpec` → `LayerNorm` node (parameterless, token‑shaped).
  - `TokenMixingSpec tokens h` → `TokenMixMlp tokens` node, shape `(tokens,h,tokens)`.
  - `PatchSpec geom size stride h o` → `PatchStem` node carrying the resolved `PatchRuntime` (positions precomputed), MLP shape `(size*size*channels+2, h, o)`.
  - `AttentionSpec w h` → `Attention` node, shape `(w,h,w*3)`.
  - `MeanPoolSpec` → `MeanPool` node.
- Widths flow through `mapAccumL` exactly as `graphNodes` does now (581–606), but tracking the **executed** channel/token width so `layerInputShape`/`layerOutputShape` are correct and the graph is *shape‑checkable end to end* (the enriched graph gains the property the executed path lacks today: a static shape contract validated once at build time).
- **Seeding** is placed on the node at build time: parameterized node at overall index `k` gets `mlpInit shape (seed + k*1009)`, where `k` counts **all** nodes in order (parameterless nodes still consume an index), reproducing `initialiseLayers`' `seed + idx*1009` exactly (see §6). `architectureLayerGraphForFamily` (445–461) is folded into this single builder; `seed` is threaded in as it is now.

`architectureSpecForProblem` (300–317) then sets only `archGraph = <this builder>`; `archLayers`/`archLayerGraph` fields are gone.

## 4. How initialiseLayers / training / forwardOnly / prediction switch onto the graph

**Initializer.** `initialiseLayers` (1822–1867) is replaced by a builder that *is* §3 (parameters are seeded at plan‑build time) plus attaching `adamInit shape` per parameterized node → a `TrainingGraph`. The per‑node validation currently in `initialiseLayer` (token count > 0, patch size/stride > 0, non‑empty positions) moves into the node builder / `mkOperatorNode` smart constructors in `LayerGraph`, returning `Either Text`.

**Forward/backward interpreter.** The bodies of `forwardLayer` (1891–1996) and `backwardLayer` (2022–2154) become a **graph‑node interpreter** in `LayerGraph` keyed on the enriched `LayerKind`, threading `BatchRep`. This is a *move*, not a rewrite: the per‑operator numerics (`attentionForward/Backward`, `layerNormForward/Backward`, `tokenMixing*Exact`, `extractPatches`/`scatterPatchGradients`, `meanVectorExact`, `deviceGradientStep`) are transplanted verbatim so outputs stay bit‑identical. `forwardOnly`/`forwardWithTapes`/`backwardAll` (1869–2020) become thin folds over `layerGraphNodes archGraph` instead of `[LayerState]`; the `LayerTape` set (267–275) becomes the graph's per‑node forward tape. The device seam is unchanged: parameterized operators still call `mlpdForwardBatch`/`mlpdBatchGradient`/`mlpdInputGradientBatch` on their `MlpParams` payload, so every backend (`MlpDevice`) drives the same graph.

**Training entrypoints.** `trainArchitectureWithDevice`, `…Selected`, `…WithDeviceForExactUpdates`, and the `ExactArchitectureTraining` machinery (739–1671) change only their state type: `[LayerState]` → the `TrainingGraph`. `trainEpoch`/`trainBatch`/`advanceExactArchitectureTraining` fold over graph nodes; `architectureLayerWeights`/`trainedArchitectureWeights`/`slmInitialWeights` (1721–1740) are re‑expressed as `graphParameterVector` over the training graph's parameterized nodes (identical order, identical bytes). `TrainedArchitecture` (162–168) replaces `trainedArchLayers :: [LayerState]` with the trained graph.

**Prediction.** `predictArchitectureWithDevice` (836–893) and `accuracy…`/`crossEntropy…` (796–829) call `forwardOnly` over the trained graph; the strict boundary checks (state/spec count agreement at 844–853) become graph‑internal invariants (the graph is already shape‑consistent by construction), and the input‑width / finiteness / single‑output guards are retained verbatim.

## 5. Serialization and Flat‑slice preservation

The serialization boundary stays **coarse** and byte‑stable:

- `projectTrainedArchitectureRuntime` (1042–1104) and `canonicalClassificationRuntimeContract` (967–1004) currently walk `archLayers`/`LayerState` pairs via `runtimeLayerContract` (1006–1033) and `projectRuntimeLayer` (1130–1244). Because the operator node set/order/shapes equal the old `LayerSpec` set/order/shapes, `RawRuntimeLayer`s — and therefore `supervisedRuntimeVirtualSlices`, `parameterCount`, slice names (`W1..b2`), and the physical blob byte order — are **identical**. `refineSupervisedRuntime` round‑trips unchanged; existing checkpoints admit.
- The strict `projectRuntimeLayer` cross‑checks (name, residual scale, token count, patch geometry/positions/input‑count, MLP shape) are preserved — now spec‑vs‑state drift becomes node‑attribute‑vs‑payload drift, structurally impossible in the unified graph but kept as a defensive refinement.

## 7. Mlp.hs stays the two‑layer special case

Mlp.hs is *already* the correct model of the relationship and needs **no semantic change**. `mlpLayerGraph` (166–200) lowers a 2‑layer MLP to exactly two fine `DenseLayer` `LayerGraph` nodes (`mlp-hidden` tanh + `mlp-output` linear); `mlpBackward`/`mlpInputGradient` (266–285) replay it through `Autodiff.runBackward`. In the unified design this is precisely the **per‑operator kernel**: each SL `DenseMlp`/`ResidualMlp`/`TokenMixMlp`/`PatchStem`/`Attention` operator that holds an `MlpParams` lowers, for its affine work, through the *same* two‑Dense‑node fine graph. So:

- Mlp.hs keeps its narrow surface (`MlpShape`, `MlpParams`, `mlpInit`, `mlpForward`, `mlpBackward`, `mlpInputGradient`, `mlpParamsToFlat/FromFlat`, the Adam optimizer, and the policy/value heads). It remains the canonical "two‑Dense‑node" builder.
- The SL operator interpreter reuses `mlpLayerGraph`‑style lowering (or shares a single `denseMlpNodes :: MlpParams -> [LayerNode]` helper hoisted so both Mlp.hs and Architecture.hs call it) — one lowering, one autodiff tape, no divergence.
- The fine single‑affine node semantics (`runLayerNode`/`backwardLayerNode`, LayerGraph.hs 398–495) remain finite‑difference‑checkable (`maxFiniteDifferenceError`); the *new* token/attention/norm/pool operator nodes get their own finite‑difference coverage as they gain real forward/backward (this is the 23.1→23.2 growth path, and is where the previously‑nominal features become genuinely implemented).

## 8. RL trainers and AlphaZero consume the same graph surface

No API break for RL/AlphaZero, by construction — they depend on Mlp.hs, not on the SL `Architecture` module:

- **RL trainers** (`RL/Algorithms/{Ppo,Dqn,QrDqn,Continuous,Her}Trainer.hs`) call `mlpForward`/`mlpBackward`/`mlpInputGradient`/`policyValueForwardWith`/`policyValueBackwardWith` on `MlpParams` (e.g. PpoTrainer `trpoPolicyGradient`/`trpoValueGradient` 614–637, DqnTrainer:441). Since Mlp.hs's surface and numerics are untouched (§7) and it already routes backward through `LayerGraph`, the trainers continue to run the *same* typed‑graph autodiff underneath, unchanged.

If desired, expose `LayerGraph.denseMlpNodes`/`operatorNodes` as the shared constructor and have both `Architecture` and `Mlp` import it, so "the graph surface" is literally one function. This is optional for correctness but is the clean way to state the convergence: SL, RL, and AlphaZero all differentiate through one `LayerGraph`.

### The decisive insight the plan must internalize

The current trained path is **not** the literal architectures — `Architecture.hs:379-420` shows every vision row is a **shared compact MLP-Mixer approximation** (PatchSpec stem → token-wise Residual-MLP blocks → one LayerNorm/token-mixing-MLP/LayerNorm mixer → one AttentionSpec → mean-pool → dense). The historical `cifar10-vit = 0.218` was produced by *this* proxy. Replacing it with REAL conv/attention changes each row's optimization landscape, and the direction is **row-dependent**:

- **CONV rows are helped.** Real Conv2D/residual blocks carry strong image inductive bias, so on CIFAR in ~40 steps a real conv ResNet typically *beats* the mixer proxy. This lowers risk for resnet20/56 and cifar100-wrn relative to the proxy — provided init/warmup are right.
- **The ATTENTION row is hurt.** A real ViT (patch-embed + genuine multi-head self-attention + MLP) is *more* data-hungry and *slower* to converge than the mixer proxy that already only reached 0.218. On 2000 images / 5 flat-LR epochs from scratch, a real ViT median will very plausibly land **at or below 0.25**. The row that already fails gets a harder architecture.

### Per-row hotspots

1. **`cifar10-vit` (HIGH, go/no-go).** Already 0.218 < 0.25 under the easier proxy; the real self-attention path removes the mixer's optimization crutch and adds data hunger. Gap-to-bar is small (0.032) but variance across 5 seeds is large for a from-scratch ViT on 2k images, so the *median* can straddle the bar. This is the row 24.2 will fail on.
2. **`cifar10-resnet56` (ELEVATED).** Depth is the enemy of few-step convergence: a real 56-layer conv net in ~40 gradient steps without warmup or identity-residual init can stall near random. Bar 0.20 partially compensates, but this is where init/warmup earn their keep.
3. **`cifar10-resnet20` (MODERATE–ELEVATED).** Real conv helps, but ~40 steps on 1000 images is a thin warmup window for a from-scratch ResNet; borderline against 0.25 without a schedule.
4. **`fashion-mnist-resnet` (MODERATE).** Easy dataset and 10 epochs, but **lr 3e-3** is high for a real ResNet with no warmup — early-step instability is the failure mode, not underfitting.
5. **`mnist-deep-mlp` / `fashion-mnist-mlp` / `mnist-shallow-mlp` (LOW–MODERATE).** Genuine, non-vacuous bars (0.90/0.81/0.90) but comfortably reachable in 10 epochs on 7000 examples; deep-MLP dropout is only 0.1 (`Architecture.hs:471,474`), mild.
6. **`cifar100-wide-resnet` / `tiny-imagenet-resnet50` (LOW convergence, other risks).** Bars 0.04 and 0.00 are trivially/vacuously met, but WRN-28-10 (~36M params) and ResNet-50 single-threaded oneDNN over 550 / few steps carry real **wall-clock/timeout** risk, and ResNet-50 at 256 train / batch 128 (2 batches/epoch) has degenerate BatchNorm running stats.

### Honest mitigations (no weakening of the anti-fabrication invariant)

The invariant is only `slack > 0` (`ExternalBars.assertProductBarExternal`) plus keeping `slLiteratureTarget` a real published number. All of the following respect it:

- **A. LR warmup + cosine decay (highest leverage, fully honest).** The path currently threads a *flat scalar* `learningRateOverride` only — no warmup/cosine exists (`grep` for `warmup|cosine|scheduler` in SL/Product is empty; `TrainingExecution.hs` threads `clfEpochs` + scalar LR). Linear warmup over the first ~10–20% of steps then cosine decay is standard, touches no bar or dataset, and directly fixes the deep-ResNet-stall and ViT-instability failure modes. Do this first.
- **B. Principled init: Kaiming/He for convs, truncated-normal for ViT patch/attention, and zero-init the last BN γ in each residual branch.** Zero-init-residual is a documented real technique that makes deep ResNets trainable in few steps; it is the honest analog of the proxy's hand-tuned `residualScale 0.5` (`Architecture.hs:334-340`), which will *not* transfer to real conv blocks. Helps resnet56/20 most.
- **C. Use more of the real product dataset (raise `supervisedTrainingExampleCount`).** cifar10-vit at 2000 and resnet rows at 1000 (`Matrix.hs:998-1005`) are the binding constraint for the data-hungry rows. Raising cifar10 rows toward 5k–10k real CIFAR images is *not* fabrication — it is the real bounded dataset — and is the single biggest lever for ViT. Cost: compute.
- **D. Raise the vision epoch budget (5 → 10–15) for the CIFAR rows.** The 5-epoch cap in `supervisedEpochBudget` (`Matrix.hs:791-798`) is a policy choice, not a literature constraint; more real epochs is honest and directly helps every borderline vision row. Cleanest lever after warmup.
- **E. Standard CIFAR aug (pad+crop, horizontal flip) is honest and helps *test* accuracy on tiny sets, but it is **double-edged under a 5-epoch cap** (heavy aug slows few-epoch convergence). Recommend only *light* aug and only paired with (D) more epochs. Do not assume it exists.
- **F. Bar/slack re-anchoring — LAST RESORT, mostly off-table.** Slacks are already very wide (0.66–0.74) and bars already low; targets must stay the real published numbers. Widening the ViT slack (0.68→0.71 ⇒ bar 0.22) is technically legal (`slack>0`, target real) but the bars are FROZEN for 24.2 and this erodes the realness signal. Prefer fixing the regime over lowering the bar.

### Realness holes 23.1 should resolve now (anti-fabrication, not convergence)

- **`tiny-imagenet-resnet50` effective bar = 0.00** (0.64 − 0.64). It passes at *any* accuracy, including 0.00 — an untrained or diverged ResNet-50 clears it. It satisfies the letter of the invariant (`slack = 0.64 > 0`, so `assertProductBarExternal` and the negative-control/lint pass) but is a tautology in spirit for a maximise-accuracy metric. **`cifar100-wide-resnet` at 0.04** is near-vacuous. 23.1 should explicitly decide whether these are convergence rows (raise the effective bar above the random floor) or reclassify them as compute/plumbing-demonstration rows — otherwise 24.2 "passes" them regardless of whether the REAL architecture trains at all, which is exactly the failure the frozen-bar invariant was created to prevent (`ExternalBars.hs:3-19`).

### What 23.1 must design around (for 24.2 to be a real go)

1. **Land a warmup+cosine schedule and principled/zero-init-residual init (A+B) as part of the real-architecture swap** — not as a 24.2 afterthought. Deep real ResNets and a real ViT will not converge in 5 flat-LR epochs otherwise.
2. **Give `cifar10-vit` a fighting regime: more real data (C) and/or more epochs (D) plus warmup (A).** Validate a dry median(k=5) for the vit row *inside 23.1*; if it does not clear 0.25 with an honest regime, that is the 24.2 no-go and must be surfaced before the bars are relied upon — not discovered at the 24.2 gate.
3. **Verify `fashion-mnist-resnet`'s 3e-3 LR against a real ResNet** (add warmup or lower it) to avoid an early-step divergence regression.
4. **Resolve the 0.00 / 0.04 vacuous-bar posture** so the anti-fabrication invariant is not satisfied only in the letter.

Net: with warmup+init (A+B) and modest real-data/epoch increases (C+D), eight of the ten rows should clear their bars, and the conv rows likely improve versus today's proxy. The residual risk concentrates almost entirely in **`cifar10-vit`**, which is the design target 23.1 owns and the single credible 24.2 no-go.
